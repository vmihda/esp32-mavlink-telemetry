# ESP32 як companion computer: телеметрія MAVLink з ArduPilot

ESP32 підключений до польотного контролера по UART і працює як companion computer. Він отримує телеметрію через MAVLink, зберігає її у CSV-файли в LittleFS і показує дані та файли у вебінтерфейсі через Wi-Fi.

## Обладнання

| | |
|---|---|
| Польотний контролер | SpeedyBee F4 V3, ArduCopter 4.7.1 |
| ESP32 | ESP32 DevKit V1 (ESP32-D0WD-V3, 4 MB flash, без PSRAM) |
| Фреймворк | Arduino-ESP32 2.0.17 (ESP-IDF 4.4), PlatformIO |

Підключення:

| FC | ESP32 |
|---|---|
| T6 (UART6 TX) | GPIO16 (RX2) |
| R6 (UART6 RX) | GPIO17 (TX2) |
| GND | GND |

## Налаштування польотного контролера

У Mission Planner або QGroundControl:

```
SERIAL6_PROTOCOL = 2    # MAVLink2
SERIAL6_BAUD     = 115  # 115200
```

Після зміни параметрів FC треба перезавантажити. Частоти потрібних повідомлень ESP запитує сам командою `MAV_CMD_SET_MESSAGE_INTERVAL`, тому параметри `SRx_*` налаштовувати не потрібно.

## Збірка і прошивка

```bash
pio run -t upload        # зібрати і прошити ESP32
pio device monitor       # консоль ESP32, 115200
pio test -e native       # unit-тести на комп'ютері
```

Бібліотека MAVLink ([c_library_v2](https://github.com/mavlink/c_library_v2)) підтягується автоматично через `lib_deps`.

## Які дані отримуються

| Повідомлення MAVLink | Дані |
|---|---|
| HEARTBEAT | режим польоту, armed/disarmed, тип апарата |
| SYS_STATUS, BATTERY_STATUS | напруга, струм, заряд у %, витрачені mAh |
| GLOBAL_POSITION_INT | широта, довгота, висота над рівнем моря та відносна |
| GPS_RAW_INT | тип фіксу, кількість супутників, HDOP |
| VFR_HUD | швидкість відносно землі та повітря, вертикальна швидкість, курс, газ |
| ATTITUDE | крен, тангаж, рискання |
| SYSTEM_TIME | час UTC від GPS |
| STATUSTEXT | текстові повідомлення FC, пишуться в журнал подій |

Назви режимів розшифровуються для коптера і літака ArduPilot.

## Зберігання у CSV

Кожне завантаження ESP пише телеметрію в окремий файл `log_<номер завантаження>_<частина>.csv`, наприклад `log_00017_01.csv`. Рядок пишеться двічі на секунду, поки є зв'язок з FC. Колонки:

```
uptime_ms,utc,boot,link,armed,mode,voltage_v,current_a,battery_pct,consumed_mah,
lat,lon,alt_msl_m,alt_rel_m,gps_fix,satellites,hdop,groundspeed_ms,airspeed_ms,
climb_ms,heading_deg,throttle_pct,roll_deg,pitch_deg,yaw_deg
```

Невідомі значення залишаються порожніми. Наприклад, без GPS порожні координати та UTC. Файл створюється лише після першого рядка телеметрії, тому завантаження без зв'язку з FC не залишають порожніх файлів. Коли файл досягає 512 KB, починається наступна частина. Якщо вільного місця в LittleFS менше 96 KB, найстаріші логи видаляються.

Окремо ведеться `events.csv`: завантаження ESP і причина перезапуску, втрата та відновлення зв'язку, повідомлення FC, видалення файлів.

Під LittleFS виділено близько 2,4 MB (див. [partitions.csv](partitions.csv)). Рядок без GPS займає близько 110 байт, з GPS трохи більше, тож при 2 рядках на секунду місця вистачає на 2...3 години запису до початку ротації.

## Вебінтерфейс

ESP32 піднімає точку доступу Wi-Fi:

- мережа `ESP32-Telemetry`, пароль `telemetry123`
- адреса http://192.168.4.1/ (або http://telemetry.local/)

На сторінці раз на секунду оновлюються телеметрія і стан зв'язку, нижче є список файлів з переглядом, завантаженням і видаленням. Файл, у який зараз іде запис, видалити не можна.

| Запит | Відповідь |
|---|---|
| `GET /` | сторінка інтерфейсу |
| `GET /api/status` | телеметрія і стан зв'язку в JSON |
| `GET /api/files` | список файлів у JSON |
| `GET /download?file=<ім'я>` | завантаження файлу |
| `GET /view?file=<ім'я>` | перегляд файлу як тексту |
| `POST /delete?file=<ім'я>` | видалення файлу |

Щоб ESP32 також під'єднувався до домашньої мережі, скопіюйте `include/wifi_secrets.example.h` у `include/wifi_secrets.h` і впишіть SSID та пароль. Цей файл є в `.gitignore`.

## Втрата зв'язку, перезапуск і повторне підключення

Втрата зв'язку. Якщо від FC 3 секунди немає HEARTBEAT, ESP записує подію `LINK_LOST` і зупиняє запис рядків. У CSV це видно як розрив у `uptime_ms`. Коли HEARTBEAT повертається, ESP записує `LINK_RESTORED` і знову запитує частоти повідомлень, бо після перезавантаження FC їх скидає. Якщо HEARTBEAT є, а дані перестали надходити, запит повторюється кожні 5 секунд.

Повторне підключення до іншого FC. Під час втрати зв'язку ESP «забуває» system ID контролера, тому підключається і до FC з іншим `SYSID_THISMAV`.

Перезапуск ESP. Номер завантаження зберігається в NVS, після перезапуску починається новий CSV-файл, а причина перезапуску пишеться в `events.csv`. Задачі MAVLink і запису у файли перебувають під task watchdog: якщо одна з них зависне, ESP перезавантажиться з причиною `TASK_WDT`.

Автовизначення підключення. Якщо валідних пакетів немає, ESP перебирає швидкості (115200, 57600, 921600, 460800, 230400) і пробує поміняти RX/TX місцями. Робоча комбінація зберігається в NVS, тому після перезапуску зв'язок з'являється приблизно за пів секунди.

## Перевірка на польотному контролері

Рішення перевірене на SpeedyBee F4 V3 з ArduCopter 4.7.1. FC живився від USB, без акумулятора і без GPS-модуля, тому напруга батареї близька до нуля, а колонки GPS і UTC порожні.

| Перевірка | Результат |
|---|---|
| Прийом телеметрії | близько 25 пакетів на секунду, 0 помилок розбору |
| Перезавантаження FC під час роботи | `LINK_LOST` через 3 с, `LINK_RESTORED` через 2,4...2,7 с, потоки даних відновились |
| Перезапуск ESP | новий номер завантаження і новий файл, зв'язок з FC через 0,5 с |
| Запис CSV | файли прочитані з флешу ESP, розрив у даних збігається з перезавантаженням FC |
| Вебінтерфейс | перегляд, завантаження і видалення файлів перевірені з телефона |
| Пам'ять | мінімальний вільний стек задач від 4,7 до 6,0 KB з 8 KB, вільна купа не менше 199 KB |

Реальні дані з цього FC лежать у [docs/samples](docs/samples):

- [telemetry_fc_reboot.csv](docs/samples/telemetry_fc_reboot.csv): лог телеметрії з перезавантаженням FC посередині запису
- [events.csv](docs/samples/events.csv): журнал подій
- [serial_fc_reboot.log](docs/samples/serial_fc_reboot.log): консоль ESP під час перезавантаження FC

## Тести

32 unit-тести на Unity перевіряють логіку, яка не залежить від заліза: розбір повідомлень MAVLink, монітор зв'язку і формат CSV. Запуск: `pio test -e native`.

## Структура проєкту

```
src/
  main.cpp             запуск задач, рядок стану в консолі
  mavlink_link.cpp     UART, розбір MAVLink, HEARTBEAT, запит потоків, стан зв'язку
  storage.cpp          LittleFS, CSV-логер, журнал подій, лічильник завантажень
  web_ui.cpp           Wi-Fi, HTTP-сервер, JSON API
  web_page.h           HTML-сторінка інтерфейсу
  config.h             піни, швидкості, таймаути, налаштування Wi-Fi
lib/telemetry/src/     декодер MAVLink, монітор зв'язку, формат CSV (без залежності від Arduino)
test/                  unit-тести для lib/telemetry
partitions.csv         розділи флешу: застосунок 1,5 MB, coredump 64 KB, LittleFS 2,4 MB
docs/samples/          дані, записані на реальному FC
```
